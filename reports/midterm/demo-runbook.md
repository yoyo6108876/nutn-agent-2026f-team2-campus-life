## UI 流程 A：工具與確認（約 2 分鐘）

保持預填需求：「請查看缺漏，整理需補件和待確認項目，再準備補件清單草稿。」點「準備補件清單」。說明工具讀取預先撰寫的固定合成評閱快照；GPT 實際決定工具呼叫與參數。

顯示三項：使用者已完成、失敗案例需補原因、附錄待確認。展開 trace，依序指出 `function_call → tool_validated → read_executed → tool_result_returned → awaiting_confirmation`。此時尚未寫入。

點「確認建立草稿」。顯示收據與 `LIVE_PASS / completed`；模型收到工具結果後產生摘要，Host 驗證摘要一致。只建立本機草稿，沒有通知老師或學生。同 ID 重送的一份草稿證據見 W01/W02 JSON；不要現場重按「準備」當成同 ID 重送。

## UI 流程 B：真正的文字語意判斷（約 1 分鐘）

切換「文字語意比對」。預填教師規格與學生內容都是合成，確認必做項後呼叫 GPT。R1 為 met，因「誰會用」仍描述對象與情境；R2 為 partial，因缺少失敗原因。展示原文引用、reason、suggestion。

說明引用存在只是可追溯性檢查，模型仍可能誤判。模型建議的原因也需學生自行查證，不能複製成未發生的事。這個結果尚未接回工具流程的固定快照。

## UI 流程 C：清除邊界（約 30 秒）

點「清除對話，開始新 Session」，切回工具流程，展開「本次記憶範圍」。看到 `memory:null`、`included:false`、`empty_session`。舊提案不能續用；本機草稿與稽核保留，不宣稱完全刪除所有資料。

## 失敗與備援

網路／配額／模型失敗時停止現場重試，顯示錯誤與未寫入／已有收據狀態。改用 [01 等待確認](screenshots/01-live-confirmation.jpg)、[02 完成](screenshots/02-live-completed.jpg)、[03 語意](screenshots/03-live-semantic.jpg)、[04 清除](screenshots/04-cleared-session.jpg)，開場說「以下是 2026-10-28、程式 6a5bc9b 的執行畫面」。

離線 fixture 可現場操作，但必須明說固定回覆、不呼叫模型。真實失敗案例直接展示 C01 基線的 `UNEXPECTED_TOOL_SEQUENCE`：模型跳過提案，Host 拒絕並未寫入，這次比較未全過。不是把失敗截掉後宣稱全部成功。
