# Week 3 一頁 Proposal

**題目：以教師範例為參考的作業規格與完成度檢查助手**

組別 02｜陳冠友 S11259039（隊長）、林崇偉 S11259031（隊員）

**使用者與問題。** 學生提交作業後想知道漏了哪些內容；老師需要快速看到補件項目與待確認事項。老師範例中的寫作方式不應直接變成必做要求，因此先由老師確認檢查清單。

**Claim。** 在已確認要求與可讀文字範圍內，系統先檢索教師要求及學生段落，LLM 再辨識換句話說、部分完成及缺少附件等情況，提供附來源的提醒。本週以三項合成要求驗證流程；不主張能自動評分、保證作業正確或適用所有課程。

**LLM 必要性。** 「剛交完報告、擔心遺漏的同學」可表達 Target User；「沒有說明原因」含有「原因」關鍵字卻未完成要求；「見附錄 A」不能證明附件可讀。規則基準在 Q1 得 0/3，實際 LLM 得 3/3。這只是一次、單一合成案例的觀察，非普遍準確率。

**資料範圍。** 本週使用專案自製教師要求三段、學生文字三段，以及三份合成羽球館公告與一份已撤回公告。預設標註 fact/role；段落是 chunk 邊界。真實師生檔案、PDF 上傳、OCR、自由問題路由及向量檢索尚未實作。Week 2 任意文字 JSON 比對 API 仍可使用；Week 3 為固定查詢實驗端點。

**流程。** 固定 query ID 路由 → 來源權限／有效期／PII／撤回篩選 → 中文雙字詞與英文詞重疊檢索 → top-k → 必要事實與角色 coverage gate → SHA-256 固定證據集 → 規則／LLM 比較 → 引用檢查 → 系統附來源與雙方提醒。LLM 看不到評測答案。

**拒答與人工確認。** 無可用段落為 `no_answer`；缺必要事實或 teacher/student 角色為 `coverage_failure`，皆不呼叫 LLM。錯誤引用、漏答與不合結構輸出拒絕。附件內容未知標 `uncertain`；不因檢索失敗直接判學生缺交。引用檢查不證明語意正確，最終仍由老師確認。

**本週驗收。** Q1 正常比對、Q2 無截止日期、Q3 top-k 不足；B1 合成多證據案例須引用一致、fact coverage 3/3、unsupported claims 0。教師原始羽球館案例尚未提供，B1 不能代稱教師指定案例已通過。詳見 [Gate 對照及證據](README.md)。
