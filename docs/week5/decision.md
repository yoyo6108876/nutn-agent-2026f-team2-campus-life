# Week 5 一頁重構決策

**決定：保留手刻原版為預設，LangGraph 候選保留為可切換實作。** 本次已接回原介面並完成 live；「保留原版」是比較後的選擇，並非尚未做出候選。

**替換什麼：** 原 `Workflow.start` 產生 pending、`Workflow.decide` 直接接續的確認編排，候選改用 `StateGraph` 的 approval／apply 節點。approval 呼叫 `interrupt()`，SQLite checkpointer 保存游標與提案；相同 `thread_id=run_id` 透過 `Command(resume=...)` 接續。讀報告與產生提案仍用原程式，不把整套專案移植到框架。

**保留什麼：** OpenAI 模型、prompt、工具 schema、MCP、來源／引用 gate、600 秒期限、可信的 UI 決定、SQLite 原子寫入與 request_id 唯一鍵、摘要核對、有限重試都保留。checkpoint 與業務交易不是同一個交易；已提交的收據優先，重播不再次寫入或重問摘要。

**實測結果：** [驗收紀錄](validation.md) 的五組九個離線案例與兩個 live 前後比較全部通過；131 項測試通過。原版與候選都能重啟接續，正常查詢各 2 次、草稿各 3 次模型呼叫。此次四條 live 流程共 11,834 tokens；候選沒有節省模型呼叫。重啟確認的離線程序總耗時由 3.431 增至 4.204 秒；live 由 9.589 至 14.535 秒，但只有一輪且含載入與模型變動，不能當作效能結論。

**得失：** 框架提供可讀的 checkpoint ID、interrupt 與接續游標，將來多個等待節點較容易描述。然而本專案現在只有一次確認，原版已具持久狀態；候選多 172 行接頭、第二個 SQLite、跨程序鎖及 2 個直接依賴（鎖檔共增 27 個套件）。本次沒有證據支持「較少程式或維護成本」，因此不把候選設為預設。

**回退與下一步：** 同一 UI 選原版，或新請求指定 `engine=baseline`；既有候選提案仍透過其 checkpoint 完成／取消，不能切引擎跳過檢查。先保留此版本與可重跑證據；若後續出現多階段人工確認，再評估讓更多等待節點共用框架。多機鎖、checkpoint 與業務收據的進一步復原、非 macOS 驗證留待後續，不在這次完成宣告內。
