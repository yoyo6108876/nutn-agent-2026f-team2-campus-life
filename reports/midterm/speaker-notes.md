# 講解與問答準備

講者備註也存於 PPTX。先理解再用自己的話講，不把下列文字當作已通過個人理解驗收。

## 每頁重點

1. 說明題目、組員、證據日期與版本。本次是本機階段原型。
2. 用「誰會用」與「失敗案例缺原因」說明問題，老師先確認必做項。
3. 單次語意比對只需 LLM；Agent 的價值在跨工具、等待確認與結果回填。工具序列有 Host 限制。
4. 說明 UI、FastAPI、OpenAI、MCP、來源、SQLite 與 Session 的關係。工具結果回傳模型後仍核對摘要。
5. 各解釋一次輸入、輸出、validator、拒絕條件與 side effect。模型不能提供 confirmed。
6. 週進度說明新增了什麼；Week 6 未核對，Week 3 指定教師案例還缺原文。
7. 最近成功摘要是 context，不能取代權威來源或先前同意。清除與交易稽核分開。
8. 展示工具流程、人工確認與收據。工具讀的是固定合成快照，不冒充新批改。
9. 展示真實語意判斷與原文引用。模型生成建議不是經查證的失敗原因。
10. 正常、跨人、清除、來源更新與重送。清楚區分 live、offline、故障注入。
11. 基線真實失敗仍保存。不能由一組比較推論記憶提升品質或降低成本。
12. 最大缺口是兩條流程尚未整合。給出能驗收的下一步。
13. 建議分工須兩人確認，說明 AI 協作與自行理解責任，進入問答。

## 常見問題與可核對回答

**為什麼不是寫關鍵字規則就好？** 標題和內容可換句話說，規則無法涵蓋所有語意對應。LLM 判斷充分性，程式處理可明確驗證的欄位、引用、版本與權限。LLM 必要不代表每一步都需要模型。

**Agent 是否必要？** 單次比較不用 Agent。本專案後續任務需要查報告、提出補件草稿、等待使用者確認、執行並回傳收據，才使用受控工具迴圈。現有模型輸出工具名稱與參數，但 Host 限制先讀後提案，沒有自由規劃多工具。

**模型選錯工具或亂給參數怎麼辦？** `Workflow.call` 檢查唯一且正確的工具序列，以 Pydantic 驗證，目標與項目必須符合原請求／報告，否則停止。C01 基線正是實際工具序列失敗。

**使用哪個框架？為什麼？** 後端 FastAPI＋Pydantic；原工具狀態機做預設，Week 5 另做 LangGraph checkpoint 候選，用於等待與接續的比較。沒有證據顯示框架數量等於品質，因此 Week 7 沿用原流程的接入點。

**兩個工具都是 MCP 嗎？** 否。`get_submission_review` 透過 MCP stdio 唯讀 server；`create_revision_draft` 是 Host 本機寫工具提案，確認後在交易中執行。MCP 不提供繞過確認的寫入入口。

**RAG 是向量資料庫嗎？** 本版以固定合成 corpus、文字／bigram overlap 檢索，保留 top-k、來源版本、引用與 coverage gate，沒有宣稱用 embeddings/vector DB。任意文字比對直接把有界文字送給模型，目前不靠該固定 corpus。

**引用正確就代表判斷正確嗎？** 否。原文引用核對只證明內容可找到。語意判斷仍需人工標註評估；可疑項目交老師確認。

**清除對話會刪掉什麼？** 刪除當前摘要並停用舊 Session，後續 context 不含舊摘要，舊 run 不可再用此 Session 接續。草稿與稽核記錄保留，尚未實作整體資料保留／實體刪除政策。

**同一使用者開很多對話？** 每個 Session 有不同 ID。摘要只留在該 Session，沒有自動跨 Session 偏好。跨人讀寫回傳泛用 `RUN_NOT_FOUND`，不透露他人的 run 是否存在。正式身分登入尚未做。

**連按確認會建立兩份嗎？** 同 run ID 在 SQLite 交易中只處理一次，回原收據。按「準備補件清單」會建立新 run，不能把不同 run 視為同一個重送。外部通知尚未實作。

**為何不是 Gemini？** 組員指定沿用 GPT，因此實作與 live 證據使用 OpenAI。課程 Google Cloud／ADC Gemini 項目是 `LIVE_NOT_RUN`，不能稱已滿足該規定，須由教師確認差異或另補驗證。

**現在可以拿任意 PDF 自動提醒老師嗎？** 尚不行。文字語意流程可運作；固定快照的工具流程可運作。PDF 解析、兩者整合、正式授權與外部通知仍待完成。
