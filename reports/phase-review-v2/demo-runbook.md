# 演示說明：每一步怎麼做、怎樣才正常

對應 [phase-review-v2.pptx](phase-review-v2.pptx)。現場操作只有第 8、9 頁，共約 3 分 20 秒；其他頁只講投影片。下面的畫面文字以 `327b7e2` 的程式為準。

## 上台前

| 步驟 | 怎麼做 | 正常 |
| --- | --- | --- |
| 啟動伺服器 | 在專案資料夾執行 `.venv/bin/python -m uvicorn assignment_checker.api:app --host 127.0.0.1 --port 8000`，這個終端機不要關 | 看到 `Uvicorn running on http://127.0.0.1:8000` |

如果啟動時出現 `address already in use`，代表 8000 埠已有舊伺服器，先停掉再啟動。

## 第 8 頁：補件工具流程（約 1 分 50 秒）

| 操作 | 正常畫面 |
| --- | --- |
| 選「示範學生 A」，按「切換／開始」 | 綠色提示「示範身分已切換，從空白 Session 開始。」，旁邊出現 `student-a ／ session-…` |
| 切到「補件工具流程」分頁（頁面預設開在 PDF 分頁） | 左邊有需求文字框和「執行方式」 |
| 執行方式選「GPT 實際 AI」，按「準備補件清單」 | 先顯示「正在查詢並驗證來源…」，再變成「結果已更新，請查看來源、狀態與待確認內容。」 |
| 看結果 | 三個項目：**使用者與需求＝已完成**、**失敗案例的輸入、結果、原因＝需補件**、**可查看的附錄測試紀錄＝待確認**。上方寫 `GPT 實際 AI · LIVE_IN_PROGRESS ／ awaiting_confirmation`（還在等你確認，這不是錯誤）。提示「提案已準備好，尚未寫入。」，並出現「確認建立這份補件清單？」 |
| 展開「查看工具、記憶與驗證紀錄」 | `audit` 依序有 `model_output`（裡面是 function_call）、`tool_validated`、`read_executed`、`tool_result_returned`，最後是 `awaiting_confirmation`，而且 `executed` 是 false |
| 按「確認建立草稿」 | 上方變成 `GPT 實際 AI · LIVE_PASS ／ completed`；提示「補件草稿已建立，尚未傳送給任何人。」；下面出現 `草稿：draft-…` 和 `請求：run-…` |
| 再看紀錄 | `live_status` 是 `LIVE_PASS`；`summary` 的 `needs_revision` 是 `failure_case`、`needs_confirmation` 是 `appendix`、`status` 是 `draft_created`；`memory_persisted` 是 true |

**也算正常：** 新 Session 第一次跑時，`memory_trace` 的 `included` 是 false、`reason` 是 `empty_session`。同一個 Session 再跑一次，`included` 會變成 true，這是有帶入上次的摘要，不是錯誤。

**不正常：** 提示變成「已停止：代碼」。例如 `UNEXPECTED_TOOL_SEQUENCE` 是模型跳過了步驟，被 Host 擋下，沒有寫入。不要重按，直接看「出狀況時」。

## 第 9 頁：語意比對與清除（約 1 分 30 秒）

| 操作 | 正常畫面 |
| --- | --- |
| 切到「文字語意比對」，保留預填內容，勾選「我已核對以上項目為本次必做要求」 | 勾選框有打勾 |
| 按「呼叫 GPT 進行語意檢查」 | 先顯示「GPT 正在比對文字…」，再變成「文字語意檢查完成；此結果尚未接入固定快照的草稿流程。」 |
| 看結果 | **R1＝已完成**（「誰會用」有描述對象與情境）；**R2＝需補件**（有輸入和結果，缺失敗原因）。每項都有老師和學生的引文 |
| 按「清除對話，開始新 Session」 | 提示「舊對話摘要已從模型 context 排除；交易與稽核紀錄仍保留在本機。」；session 編號改變，第 8 頁的結果從畫面消失 |
| 切回「補件工具流程」，展開「本次記憶範圍」 | `"memory": null`，`included` 是 false，`reason` 是 `empty_session` |

**也算正常：** 理由和建議的文字每次不一樣，只要 R1、R2 的狀態相同就好。清除後草稿和稽核紀錄還在本機，這是設計如此。

**不正常：** R1、R2 的狀態和上面不同，這是模型判斷變了，照實說「模型這次判斷不同，所以引用對不代表判斷對」，不要重跑到對為止。出現「請先確認必做項目」只是忘了打勾。

## PDF 預檢：正式時間不跑

跑一次約 35 秒，會超時，而且這組 PDF 彩排時失敗過。第 10–12 頁只講投影片。問答時若要示範，只用 `examples/week6` 的 `teacher.pdf` 和 `student.pdf`，不要投影真實學生作業。

| 結果 | 畫面 | 怎麼說 |
| --- | --- | --- |
| 成功 | `LIVE_PASS ／ 老師 teacher.pdf（2 頁）／學生 student.pdf（3 頁）`，四項配分（40／20／20／20），標出缺標準差、缺改進方向 | 勾選核對配分後才看得到預估區間。若模型把終端機截圖判為已完成，那是已知誤判：報告裡只有文字形式的輸出 |
| 被擋 | `未產生報告 · INVALID_SOURCE_REFERENCE`，「模型選擇的來源或頁碼不符。」 | 這是模型選錯證據，Host 拒絕給分。安全機制有作用，但這次預檢沒有成功，不要說成通過 |

選「候選」時，畫面會多列每份草稿的結果、呼叫次數和停止原因，最多呼叫 2 次。

## 終端機紀錄怎麼看

| 紀錄 | 意思 |
| --- | --- |
| `200 OK` | 正常 |
| `GET / 404`、`GET /favicon.ico 404` | 正常，沒有首頁和網站圖示 |
| `GET /assistant/week7/session 401` | 登入前正常，按「切換／開始」後就會變 200 |
| `POST …/pdf/precheck 502` | PDF 沒有產生報告，原因看網頁上的錯誤訊息 |
| `Traceback` 或 `500` | 不正常，改用截圖 |

## 出狀況時

1. **不要一直重按。** 先把畫面上的錯誤講出來。
2. **第 8、9 頁的備援：** 開 `reports/midterm/screenshots/` 的 `01`–`04`，並說「這是 2026-10-28、程式 6a5bc9b 的執行畫面」，不能說成現場成功。
3. **第 8 頁也可以改用離線：** 執行方式選「離線示範」，並明說是固定回覆、沒有呼叫模型。畫面會寫 `離線示範 · 未呼叫模型`，紀錄裡是 `LIVE_NOT_RUN`，這樣才正常。語意比對沒有離線模式，只能用截圖 `03`。
